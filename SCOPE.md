# DealScreener — Scope

**Goal:** a portfolio MVP proving the OM → first-pass screen concept for
real estate investment: fictional offering memorandums in, structured
underwriting summary + gap report + cited memo shell out, human-in-the-loop
throughout. Explicitly **not** autonomous underwriting.

## In scope

1. **Fictional OM corpus** — 3 synthetic OMs generated by
   `scripts/generate_oms.py` (reproducible, seeded content):
   - `maple_grove_apartments.pdf` — clean digital multifamily OM (8 pp.)
   - `harbor_point_mixed_use.pdf` — messy mixed-use: nested expense table,
     one scanned-style page
   - `ironworks_industrial.pdf` — small industrial with deliberate gaps
     (no expense breakdown, no stated cap rate)
   - Ground truth emitted alongside to `data/ground_truth/*.json`.
2. **Extraction pipeline** (`src/`) — PDF text extraction with page numbers
   → field extraction (OpenAI structured-output provider, or a narrow
   no-key local template provider) → normalization to the firm-template
   schema.
3. **Guardrails** — structured output with `NOT_FOUND` refusal (never
   hallucinate a number); page citation required per field; deterministic
   reconciliation in code (unit counts, weighted rents, expense sums,
   cap-rate math); unsourced fields flagged amber.
4. **Outputs** — normalized JSON (firm-template schema), gap report with
   broker questions, cited first-pass memo shell (facts + gaps only).
5. **Demo UI** — upload a PDF, see fields with citations, reconciliation,
   gaps, and the memo.
6. **Eval** — field-level accuracy vs ground truth across the 3 OMs;
   money-moving fields weighted 3×.

## Out of scope (deliberately)

- A client's real Excel template (that mapping is the paid-pilot
  customization, done per engagement).
- Autonomous underwriting decisions, investment thesis, or go/no-go.
- Deep rent-roll / T-12 parsing as separate document inputs (v1 is
  OM-only; documented as a Phase-2 extension).
- Real broker, property, or market data — everything is fictional.

## Non-goals

Replacing the analyst. The product thesis (per the viability research) is
reviewer time 4–5 hrs → ~15–30 min of citation checks, with a named human
reviewer always in the loop.
